# 鸿图界面统一规范

本规范用于全部原生界面。视觉模板决定信息排布，设备 DPI 只用于 px/vp 换算；业务数据、单位、状态和可用条件来自实际服务。新控件复用 `common/UiTokens.ets` 与 `COLORS`，不自行发明圆角、颜色或尺寸。

## 形状与尺寸

| 组件 | 规则 |
| --- | --- |
| 普通、图标、主次及危险按钮 | 显式 `ButtonType.Normal`，圆角 **8vp** |
| TextInput、TextArea、Search、Select | 圆角 **8vp**，单行输入高 **40vp** |
| 普通操作按钮 | 高 **36vp**，字号 **13fp**；密集工具栏图标按钮 **32vp**，图标 **18vp** |
| 分段选择 | 外框 **8vp**，选项 **6vp**，统一蓝色选中反馈 |
| 悬浮工具窗、属性窗、卡片 | 圆角 **12vp**，内容边距 **16vp** |
| 居中模态对话框 | 圆角 **16vp**，内容边距 **24vp** |
| 状态标签 | **6vp** 圆角，不套用操作按钮的视觉样式 |
| 画布几何、色标、表格分隔线 | 按数据与绘制语义显示，不能为了 UI 圆角改动版图几何 |

圆角要在最终边框样式之后生效：使用 `.border({ ..., radius: UI.controlRadius })`，或将 `.borderRadius(UI.controlRadius)` 放在 `.border(...)` 后。不得依赖默认胶囊按钮或边框的默认半径。

系统窗口、原生菜单、系统确认框和桌面服务卡片由系统管理材质与形状；应用不另外画一套系统控件。圆形按钮只用于明确的圆形发送/停止语义控件，直径固定 36vp；不能把普通操作做成圆形或胶囊形。

## 操作角色

| 角色 | 用途 | 视觉 |
| --- | --- | --- |
| 主操作 | 一个操作分区内最主要的提交/运行/应用动作，最多一个 | `COLORS.primary` 底、白字 |
| 次操作 | 取消、关闭、导入导出、辅助动作 | `COLORS.surfaceMuted` 或 surface 底、ink 字，边框 `COLORS.border` |
| 危险操作 | 删除、丢弃、解除等不可直接恢复的动作 | `COLORS.dangerSoft` 底、danger 字；沿用实际业务确认机制 |
| 文字动作 | 表格行中的进入、定位、展开等 | 透明底、primary 字；仍为 Normal 类型与 8vp 交互区域 |

同一行先放内容，右侧放动作；对话框底部次操作在左，主操作在右。图标按钮需有名称、tooltip/无障碍文本；不可用状态沿用原生 `.enabled(false)`，不能只变色而继续响应。键盘焦点显示 2vp 蓝色边框，焦点不改变控件形状。

## 菜单与导航

- 所有应用功能菜单（顶部、工具栏、右键、长按、二级）复用 `common/WorkbenchMenuStyle.ets`。每个动作和分类都有语义图标，禁止同层混用纯文字项、图片图标、emoji 和 Symbol 图标；同一功能在各入口复用同一个图标及名称。
- 原生菜单统一使用 `menuStyle(实际菜单项, this.getUIContext())`，菜单项使用 `MENU_ITEM_STYLE` / `MENU_DANGER_ITEM_STYLE`。图标 **18vp**，菜单行 **44vp**，正文 **13fp**，右侧辅助标签 **11fp**。宽度按当前窗口的实际文字、快捷键、首末图标及必要原生边距测量，不设固定宽度或宽度区间；图标和文字靠左，不能预留空的左侧勾选列。系统负责分隔、焦点、悬停、禁用及弹出位置。全入口采用同一原生模糊材质，不能另外绘制仿菜单浮层。
- 每行保持“语义图标 → 动作名称 → 快捷键 / 原生子菜单箭头”的顺序。快捷键用 `labelInfo` 放入右侧列，必须对应实际按键行为，不能塞进名称或沿用不准确的标注。
- 相似设置保持同样的分组、名称和顺序：过滤按“图层范围 → 图形类型”，层级按“当前 Cell → 2/3/4/5 → 全部”，变换按“旋转 → 镜像 → 缩放”，图层按“外观 → 显示/锁定/允许选择 → 选择动作”，Cell 按“进入/新建 → 编辑 → 删除”。宽屏下拉和窄屏二级菜单复用同一 builder，不维护两份排序。
- 可切换、互斥设置显示真实 `.selected(...)` 状态，右端通过 `menuCheckIcon(同一状态)` 显示原生 Symbol 勾选标记，保持左边的图标与文字对齐。危险动作统一红色图标及文字，独立分隔并放在最后；不可用项保留真实 `.enabled(...)` 条件。
- PC 工作台统一原生侧向展开，每层按自身内容测宽；触屏模式统一原生堆栈展开，保留同样的分组、内容及顺序。原生堆栈沿用根菜单宽度，根菜单因此按自身与所有实际可见子菜单的测量值取最大值，不使用固定宽度；隐藏分支不参与测量。触屏自动子菜单箭头按系统实际 24vp 计入，避免长文案或快捷键换行。
- 功能菜单最多 **两级**：一级分类 → 二级动作。不得再嵌套第三层。
- 一级最多 **7 个入口**；二级每个语义组最多 **7 个动作**，整个弹出层最多 **12 个动作**。同组按使用顺序排列，危险操作位于本组末尾。
- 顶部“更多”按文档工程、查找器件、工艺验证、辅助工具、视图面板分类；画布右键按编辑、变换、对齐分布、布尔与 Cell、选择图层、验证网络、视图导出分类。
- 二级菜单不再包含 `builder` 子菜单。常用操作仍保留工具栏、快捷键与搜索命令入口。
- 图层、Cell、模型等可变数量的数据枚举不属于动作菜单：使用原生选择器或可滚动数据列表，不人为截断真实条目，不引入新的功能层级。
- 操作立即执行、切换状态或展开菜单时不加省略号；需要用户继续填参数或选择文件的动作使用“…”；有快捷键的动作以统一格式显示。
- Tabs 和侧栏只承担模块或内容切换，不能把提交/删除等动作混入导航。

数据/模型等原生 `Select` 属于值选择控件，保持系统选择和真实数据条目，统一 40vp 高、8vp 圆角，不把动态值伪装成功能菜单。菜单修改后还需运行 `python tools/menu_ux_audit.py`，检查全入口图标、样式、快捷键、状态标记及原回调/禁用条件。

## 排布、字阶与状态

- 间距采用 **4/8/12/16/24vp**，相同分区使用相同边距；短滚动内容顶部对齐。
- 页面标题 28fp，面板/弹窗标题 18fp，正文与控件 13fp，辅助说明 11fp；数值、路径、脚本使用既有等宽字体。
- 表单标签与输入列对齐，单位独立且固定宽度；表头与行共用列宽，48vp 标准数据行、40vp 密集结果行。
- 选中使用 primary/primarySoft；成功、警告、错误分别使用 success、warning、danger。状态还必须有文字或图标，不能只依靠颜色。
- 等待状态显示实际 busy 状态并阻止重复提交；空、失败、未配置、不完整与通过分别显示真实结果。示例参考图不提供真实检查结论。
- 窄屏按分区堆叠、收敛工具按钮和合并选项入口；不能压缩字号或让操作超出窗口。手机侧栏省去计数列以保留图层名称。

## 手机与宽屏适配

桌面工作台以画布为主：模块栏默认 **56vp**，图层侧栏默认 **240vp**，属性栏默认 **280vp**。文档名、未保存状态只在文档页签显示；顶部保留全局搜索、面板开关和常用入口。当前 Cell 的共享编辑范围显示短摘要，“范围”入口保留完整引用与影响说明。

图层面板将 `.lyp` 导入导出放入标题旁的原生菜单；视图预设选择与管理入口共用一行。圆、椭圆、圆环、圆弧收进同一“曲线”原生菜单。原有动作、对象和禁用条件不随排布改变。

未选中对象时默认收起桌面属性栏；选中后使用覆盖面板，保持画布尺寸。用户固定属性栏后，空间足够时内联显示，取消选择也保留面板。图层宽度支持 **220–400vp**，属性宽度支持 **280–480vp**；原生分隔线拖动结束后记忆宽度，固定偏好也持久化。窄窗临时约束不覆盖用户的宽度偏好。

扣除模块栏后，左栏内联需要保留至少 **480vp** 内容空间；右栏内联需要在扣除左栏后保留至少 **520vp** 画布。不足时使用原生覆盖侧栏，并通过顶部开关访问，避免缩小文字。验证结果继续使用底部 DRC 区域。

模块切换使用约 **220ms** 的短过渡；业务状态立即更新，不等待动画结束。支持系统减少动态效果设置，并在“更多 → 辅助工具 → 减少动态效果”提供持久化应用设置，供旧系统使用。开启应用设置或系统设置中的任一项，均停用自定义位移与缩放过渡；销毁工作台时移除监听和待执行的面板尺寸回写。

普通手机竖屏保留触屏布局。横屏手机、系统密度下宽度达到 768vp 的窗口，以及宽度至少 360vp 且宽高比达到 0.72 的阔屏手机，直接使用 PC 工作台。判定读取窗口像素与系统密度，避免自定义密度反过来改变模式；转回普通竖屏时恢复系统密度。

手机 PC 模式的应用密度为 `max(0.5, min(系统密度 × 0.8, 窗口像素宽 / 960))`，使工作台获得更宽的内容空间。只调整本应用窗口，不修改设备 DPI；原生 PC / 2in1 保持系统密度。小于 480px 的极小窗口受密度下限约束，不能保证 960vp。API15 起支持应用自定义密度，API20 起对子窗口同步；API12–14仍能切换PC布局，但保持系统密度。系统窗口密度查询不可用时回退显示密度。

## 验收与维护

每次界面调整必须检查：最终按钮形状、输入对齐、主次关系、菜单层数与条数、焦点和禁用状态、短内容顶部对齐、窄窗口空间。使用实际构建与原生截图/UI 树核对。参考图册和原生对照图册分别保存；桌面模拟器验证不等于手机、平板或实机验收。

本次继续调整的逐页记录见 `docs/validation/ui-redesign-20261001/continuation-report.md`，前一轮记录保留在 `report.md`。后续新增页面继续先生成参考，再用本规范实现。
