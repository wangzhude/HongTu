# AI 助手使用说明

## 全工具接入（2026-10-09）

当前版本注册 **176 项原生工具**：28 项查询、43 项可整批撤销的编辑、83 项独立操作、22 项需要原生界面配合的流程。命令面板及补充专业面板的 **49 个入口**也均可调用。完整目录与验证边界见 [全工具接入记录](validation/ai-all-tools-20261009/report.md)及[工具清单](validation/ai-all-tools-20261009/tool-catalog.md)。

模型通过 `list_native_tools` 按分类或名称获取当前工具和参数协议，通过 `read_native_tool` 读取当前结果，通过 `propose_native_tools` 提出待审阅操作。可直接调用 PCell、端口、光学/电气布线、布尔、层表达式、Clip/Fill、Cell 维护、实例操作、导入合并、DRC/LVS、报告与豁免库、视图/书签/叠加、图层样式、标尺、宏、器件库、工程恢复及 Python 脚本/扫参等实际服务。

例如：“查看这两个端口的具体实例路径，预览连接并报告最小弯曲半径”“把这些对象改到 L68/D20，检查规则并说明结果”“按这些参数生成 PCell”“对当前文档运行脚本，扫描三个宽度，把结果保留在历史中”。布线返回真实长度、半径、端点误差及近似误差；工艺检查区分完成、通过、未通过和不完整。

所有写操作仍先展示方案。应用时再次校验文档、版本、Cell 和选区；只有纯编辑工具能组合为一个事务，失败恢复整批，成功后可一次撤销并复检。文件写入、脚本执行和设置变更单独确认。文件选择器、系统授权、报告最终确认保留原生交互，回执明确区分已执行、产物已生成、后台作业已启动和等待用户操作。宏录制期间先结束录制再应用原生编辑批次。

导入合并先调用 `import.select` 选择来源，`import.selected` 查询 Cell/图层/DBU，再用明确映射调用 `import.apply`；来源或目标变化会失效。Python 运行支持只生成产物、打开独立文档和合并；扫描结果保留在历史，可通过 `python.history_apply` 载入。历史脚本和宏按片段读取，避免大脚本挤占上下文。

需要同时使用更新后的 HAP 与电脑伴随服务；健康检查应含 `assistant-native-tools-v1`。本轮电脑服务已更新，客户端仍须安装新构建；原生设备交互和真实供应商端到端执行的验收状态见记录，不能由宿主测试替代。

## 2026-10-09 增强功能

当前源码新增实时明细查询、执行回执、任务恢复记录、独立修改分组、专业流程入口、工具调用诊断，以及阵列参数模板和按文档保存的设计说明。构建与宿主测试已完成；本轮模拟器安装被自动审批拦截，新增界面尚未通过原生验收。完整证据与限制见 [本轮记录](validation/ai-workbench-20261009/report.md)。

启用“版图上下文”后，模型可按当前 Cell、图层/Datatype、对象 ID 或区域查询真实图形，并分页查询 Cell、规则、当前 DRC 与端口。返回值包含 nm 坐标单位、DBU、文档版本、总数及下一页标记。摘要和单个图形的点数仍有上限；截断会明确标记，不能把摘要当作完整几何。区域查询是包围盒候选，实例内部没有展开；端口定义不代表网络已连通。关闭版图上下文时，实时查询也会拒绝。

“待应用的修改”展示预计尺寸变化，并支持定位到画布。只有明确指定不同对象、没有相互依赖的移动/删除/旋转/镜像/缩放操作可分组接受；创建、隐式选择和重复修改同一对象的指令仍作为整体确认。实际应用再次核对文档、版本、Cell、图层及选区，成功后组成一次撤销并运行当前规则复检。回执区分几何已应用、检查未完成、检查范围不完整和回执未保存。

“分析复检结果”发起只读分析，将实际执行回执和当前检查结果交给模型。进一步修复需要用户提出新任务，并继续经过方案确认。不会把“没有可执行规则”当作检查通过。

专业工具现在可提交完整参数并由真实原生服务执行；需要人工操作时仍可通过 `workbench.invoke` 打开对应界面。进入界面不代表已完成布线、布尔或器件放置。

参数模板可填写阵列行数、列数和 nm 间距，先生成待发送的需求；发出后可生成选区阵列提案。阵列保留原图，复制真实选区并保留图层/Datatype 与图形元数据。每个方向最多 1000，行列乘积最多 10000，实际新增对象及坐标点还受编辑器预算限制。

“上下文”中的文档说明用于保存该文档的网络命名、设计约束等文字，最多 8000 字符，自动记录修订号，最多 128 份文档说明。切换文档时隔离编辑草稿；仅在版图上下文开启时发送给模型。此功能是显式文字说明，不是外部文件检索知识库。

供应商设置中的“工具调用诊断”使用当前草稿模型，实际调用一个只读工具并接收流式答复。没有版图、没有历史、不能编辑；只有工具事件与服务端执行标记都到达才显示通过。它会产生一次正常模型请求，不能替代真实版图任务的质量验收。

## 供应商与模型

打开顶栏“AI 助手”，点击面板中的“供应商/模型”；紧凑布局的相同入口叫“供应商模型”。聊天上方固定显示当前保存的供应商和模型，历史滚动不会遮住该信息。

1. 点击“新增供应商”，填写配置名称和实际服务地址。新草稿使用 OpenAI 兼容协议，不预填模型 ID 或别的供应商凭据。Ollama 使用“协议”选择器切换；“快速模板”可选，“自定义连接”表示当前草稿不与某个模板完全一致。
2. 填写该供应商的 API Key。无认证的本地 Ollama 可留空。模型地址可填兼容 API 基址或完整 `/chat/completions`；仅主机地址按 `/v1` 处理，网关前缀保留。Ollama 可使用 `/v1` 或 `/api/chat`，Agent 会使用对应兼容工具协议。
3. 点击底部固定操作区的“一键获取模型列表”。“列表地址”通常留空；网关有独立接口时填写实际 HTTP(S) 列表 URL。OpenAI 兼容响应读取 `data[].id`，Ollama 读取 `models[].name` 或 `model`。GET 使用当前连接草稿与超时，不需要先填模型 ID，也不受尚未填写好的温度、输出和上下文参数阻断。
4. 从返回的原生选择器选择模型。选择只修改草稿；即使模型 ID 已保存，当前地址、密钥和参数也会保留。填写合法的生成与上下文参数，点击“保存配置”才保存并启用该配置。
5. 同一个供应商增加第二个模型时，点击“新增模型”填写 ID，或重新获取列表后选择未保存的 ID，再保存。不同模型的温度、输出、超时和上下文参数分别保存。供应商地址和系统凭据由该供应商共用。

“已存配置”和“保存模型”选择器用于切换到已保存值，切换前应保存当前草稿。新增、删除与切换已有配置不删除会话历史；删除供应商只移除该供应商及其凭据。至少保留一个供应商，每个供应商至少保留一个模型。

获取过程显示实际等待状态，可“取消获取”。401/403、404、429、超时、网络错误和空列表都会显示具体反馈。关闭或改连接后，旧请求结果不会发布到新草稿。供应商不提供列表时可以手动填写模型 ID；列表出现某模型不代表它支持工具调用或保证推理质量。“测试连接”使用当前草稿发起模型请求，不保存草稿。

“演示模式”仍可通过协议或模板明确选择，只演示本地指令，没有远程模型列表。切换实际协议并填写地址后才可获取列表。

## 系统凭据读取失败

API Key 使用 HarmonyOS 系统 Asset，普通配置不保存密钥。读取失败时，界面会提示原凭据状态未知；空白输入不能覆盖已有供应商。点击“重试读取已存配置”会重新加载保存的字段和凭据，也可明确填写新的 API Key 后保存。恢复读取后，用户主动清空密钥再保存仍表示删除该供应商的密钥。新增无密钥 Ollama 配置不受另一个供应商读取失败的影响。

## 多轮 Agent 任务

真实模型任务由现有 Agent / AG-UI Harness 路径执行，需要电脑上的 Python 伴随服务和支持工具调用的模型。CPython 与 KLayout 不嵌入 HarmonyOS 应用。电脑服务的安装、启动和设备转发见 [Python API 与电脑伴随服务](python-api.md)。供应商设置与模型列表 GET 可在伴随服务未运行时独立使用。

聊天上方固定显示 Agent 连接状态，并提供“Agent 连接设置”直接打开已有连接面板。填写电脑伴随服务地址和访问令牌后，可在模型设置中“检查 Agent 连接”。检查通过只证明伴随服务在线并提供 Agent 协议；实际模型、工具执行和推理质量在任务运行时验证。

电脑端首次安装须按 Python 伴随服务说明安装完整 `python/requirements.txt`，其中包含 Agent SDK。后台会检查实际 SDK 版本和导入结果；缺依赖时普通几何服务仍可使用，Agent 检查不会误报成功。Agent 请求的 503 依赖错误需补齐本地依赖并重启伴随服务，详见 [主工作树修复与验收](validation/ai-runtime-main-20261006-01/README.md)。

输入任务并发送后，会话展示模型实际返回的文字、执行计划、规划步骤状态、工具参数和实际工具结果。可用工具包括读取当前版图、规划与更新任务、Python/KLayout 版图生成，以及提出受支持的原生编辑方案。失败结果会返回模型并记录在会话中；历史“运行中”步骤不会冒充完成。

对当前版图的修改先展示“待应用的修改”，由用户选择“应用修改”或“取消”。应用检查文档、版本、当前 Cell、图层和选区边界；上下文过期会拒绝应用。成功修改使用原生事务与撤销流程。新生成的版图通过受保护的载入流程打开独立文档，不把工具提案本身标记成已应用。

“继续任务”和“重试未完成”使用本地持久任务记录与当前会话历史，发起新的恢复轮次；记录包括原目标、执行策略、文档身份、工具结果、应用阶段及回执，不是完整 SDK 执行栈快照。未完成的修改不能迁移到另一文档；已应用或已结束的任务继续时只允许核对说明。若上次停在“应用中”且最终回执不完整，会阻止重放并要求先核对实际版图。待确认方案重开后仍需重新生成和审阅。继续依赖“上下文”中的聊天历史选项。

“恢复生成产物”可在原文档中下载已经生成但尚未载入的结果，无需再次调用模型。电脑端持久缓存最多 4 份、合计 32 MiB，保留最多 24 小时，超限会淘汰较早结果。已载入产物 ID 会写入任务回执防止重复；失效、所属任务不符、固定验证缺失或标签已满都会拒绝载入。缓存与任务记录分别保存在电脑伴随服务和客户端，需要两端都更新。

恢复轮次保留原用户目标和执行策略，冷重开或压缩会话后仍承接。原反相器生成任务的固定 `generic_inverter` 检查不能被重试文案、空验证参数或编辑提案绕过；新发的具体任务重新确定策略。旧会话没有任务字段时，只从最近的具体用户请求恢复，无法确定目标会提示重新输入。

解释、否定绘制、只读检查和裸电路名称允许读取、规划与答复，不能生成新文档或提出可应用的修改。自动生成须有明确生成意图；“移动选区”“左移矩形”等编辑及模糊的非电路请求仍可产生待确认提案，应用前继续核对真实编辑器上下文。底部显示“当前编辑”Cell 与工程 Top，详情也分别说明，进入子 Cell 不会把 Top 当作当前编辑目标。

任务目标副本与消息在保存时使用当前已载入请求的已知密钥、令牌脱敏；不会额外读取其它供应商凭据。此处理不代表已清理历史版本所有可能包含凭据的用户文本。

“取消生成”先停止前端等待、忽略迟到事件，再向拥有本次任务的伴随服务发送取消并查询终态。只有模型任务结束、受控工具进程停止且服务端确认终态时才显示“均已停止”；旧服务、断网或清理尚未结束会明确显示“尚未确认”。连接修改和模型切换在任务运行期间受锁保护。
