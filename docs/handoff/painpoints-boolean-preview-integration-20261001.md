Root's native build20 inspection narrowed the initial-preview defect to TextInput initialization callbacks. `aboutToAppear` computed a successful preview, then output layer/datatype `onChange` received the same existing text and cleared that preview. Manually updating the preview worked. The optional `@State preview` field was an earlier hypothesis, not the verified cause.

`BooleanPreviewDialog.ets` now retains the service payload in private `previewResult` and binds the result label, canvas, area and submit button to `@State previewReady`, `previewOutputs` and `previewArea`. `clearPreview()` clears these together. Both output-field callbacks return immediately when the incoming value equals the existing field. An actual text change updates the field, clears the previous result and asks the user to update the preview. Select explicitly displays `BOOLEAN_LABELS[this.opIndex]`.
